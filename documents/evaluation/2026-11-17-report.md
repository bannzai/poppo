# Poppo (画面のチャットを読んで翻訳と返信案をキーボードに出す iOS アプリ) の評価レポート

## 結論

**作る**

決め手は実現性で、案の中心 (背面で画面を取り込み続け、読み取り・翻訳・返信案の生成を回してキーボードに出す) が iOS 27 の実機で成り立つかは、文書からは確かめられなかった。作り手の目的は未確認だが、目的 4 通り (収益・学習・ポートフォリオ・自分が使いたい) のどれを置いても必須の観点に × は無く、判定は 4 通りとも「作る」になる。最初に作るものを「実機で中心の流れが成り立つかを確かめる版」にし、成り立たなければそこで打ち切る。

- 作り手の目的: 目的未確認 (入力に収益の記述が無いため仮定しない)。入力の「使いたい技術」「取り込みの実装を残りの構想に流用できる」からは学習・技術の蓄積の比重が読めるが、推測であり確定ではない。目的ごとの判定は「観点別の根拠」の表の下に並べた

## 前提と仮説

- 誰の: 外国語のチャット (Slack・Discord など) を読み書きする人
- どの場面の: iPhone でチャットアプリを開き、相手の発言を読んで返信する時
- どの痛みを: 翻訳アプリとチャットアプリの間でコピーと貼り付けを往復すること、訳が会話の流れを踏まえないこと
- 何で解決するか: 本体アプリが画面を取り込んで文字を読み、翻訳と返信案を作る。カスタムキーボードを開くと直前の翻訳と返信案が出て、タップで入力できる
- 今の代替手段: 翻訳アプリへのコピーと貼り付け、翻訳キーボード (自分が打った文を訳す)、スクリーンショットを選んで返信案を出すキーボード、画面を読んで返信を書くキーボード (BossAI)
- 仮定した数値: 目標月間収益 10 万円、月額 600 円、買い切り 1,500 円、訪問から有料への転換 2%、月次解約 15%、ストア手数料 15%。どれも出所の無い仮の値で、試算の形を示すために置いた

目的ごとの判定 (必須の観点に × があれば「作らない」):

- 収益: 必須はマネタイズ (△) と需要 (△)。作る。ただし到達できる流入が未判定で、JP の評価件数は小さい
- 学習: 必須は実現性 (△)。作る。iOS 27 の新しい API を使う必然性がある
- ポートフォリオ: 必須は競合・代替 (△) と実現性 (△)。作る。BossAI との違いを「翻訳と返信を 1 つにまとめた」と説明できる
- 自分が使いたい: 必須は実現性 (△) と作り手の文脈 (○)。作る

需要と競合は「画面を読んで返信する」ことに価値があることを示しているが、その価値は BossAI が先に出している。この案に残る差は翻訳との組み合わせで、差が効くかは外国語のチャットを日常的に読み書きする人が実際に使い続けるかでしか分からない。

## 数値の単位と出典

- 評価件数は iTunes Search / Lookup API の `userRatingCount` で、国ごとのストアの累積の件数。文章つきのレビュー数でも利用者数でもない。取得日 2026-11-17。取得した一覧はリポジトリに入れていない (表の「出典」の `demand/apps.tsv`・`demand/reviews/` は評価時の作業ディレクトリのファイル)
- レビューの引用は iTunes の RSS (最新順・高評価順・低評価順) から取った
- BossAI の説明文と更新日は iTunes Lookup API (JP、2026-11-17 取得)。価格はストアのページの表示に ¥600・¥1,500・¥10,000・¥25,000 があることを確かめた。それぞれの期間 (週・月・年・買い切り) は調査の報告で、自分では確かめていない
- 課金の試算は `estimate-monetization.sh` の出力で、入力の値はすべて仮定
- Claude API の Haiku 5.5 は入力 $0.10 / 出力 $0.50 (100 万トークンあたり、プロンプト 10 万トークン以下)。入力 1,500・出力 500 トークンの仮定で 1 回 $0.0004 (https://platform.claude.com/docs/en/about-claude/pricing 、2026-11-17 取得)
- ScreenCaptureKit: https://developer.apple.com/documentation/screencapturekit 、 https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios
- キーボードと共有コンテナ: https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard (「prevents writing to the containing app's shared group containers (reading is permitted)」)。2017 年更新の旧文書は「cannot share a container with its containing app」と書いていて食い違う (https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html )
- 背面での Neural Engine: iOS 27 のリリースノート「Access to the Neural engine when your app is in the background requires the new entitlement: com.apple.developer.background-tasks.continued-processing.inference」(https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-27-release-notes )
- Translation と simulator: 「It doesn't translate text in iOS or iPadOS simulators.」(https://developer.apple.com/documentation/translation/translating-text-within-your-app )
- App Review Guidelines 4.4.1・2.5.14・5.1.1(viii)・5.1.2(i): https://developer.apple.com/app-store/review/guidelines/ (2026-11-17 取得)
- Private Cloud Compute の利用条件: https://developer.apple.com/private-cloud-compute/ (Small Business Program に加入、first-time downloads が 200 万未満、entitlement の割り当て)

## ユーザーが判断する事項

- 作るか (作る / 作らない)。元の案 (翻訳と返信案をキーボードに出す) のほかに、懸念を小さくする代替として「返信案を外し、画面の翻訳だけをキーボードに出す」がある (審査の 4.4.1 と、生成が背面で動かない懸念が消える。差は BossAI に対して翻訳だけになる)
- 作り手の目的 (収益 / 学習 / ポートフォリオ / 自分が使いたい)。判定は 4 通りとも「作る」だが、課金の有無と公開後の基準の重みが変わる
- 返信案を作るモデルの経路: 端末内だけ / Private Cloud Compute の entitlement を申請する / Claude API を使う。端末外へ送る 2 つは、チャットの内容 (相手の発言を含む) が端末の外に出て、同意の画面とプライバシーポリシーの記載が要る。Claude API は費用と秘匿情報の登録が増える
- 課金: 無料で出す / 買い切り / 月額。競合のレビューで最多の不満が課金 (数回で課金画面、週額) であること、端末内だけなら原価が 0 に近いことを踏まえて決める
