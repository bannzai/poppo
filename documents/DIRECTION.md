# 方向性: Poppo

## 仮説

外国語のチャット (Slack・Discord など) を iPhone で読み書きする人は、翻訳アプリとチャットアプリの間でコピーと貼り付けを往復している。本体アプリが画面を読み取って翻訳と返信案を作り、キーボードを開くだけでそれが出てくれば、アプリを切り替えずに読んで返信できる。

評価の全文は [evaluation/2026-11-17-report.md](evaluation/2026-11-17-report.md) (評価した時点の記録で、以後の更新はこの文書に書く)。

## 判定基準

| 指標 | 計測元 (skill / コマンド) | 継続のしきい値 | 打ち切り条件 | 転換の条件 |
| --- | --- | --- | --- | --- |
| 実機で、背面の一連の処理 (取り込み → 読み取り → 翻訳 → 返信案 → キーボードに表示) が回った回数 (公開前) | 開発者メニューの診断の記録を実機で見る (ユーザー作業の一覧 issue の「実機・実環境での確認」) | 10 回試して 8 回以上 | 10 回試して 0 回で、本体アプリを前面に戻した時だけ処理する形でも成り立たない | 背面では回らないが前面に戻すと回るなら、キーボードを開く前に本体アプリへ戻る形に変える |
| 公開後 14 日のダウンロード数 | App Store Connect の Sales and Trends (取得するコマンドは公開の前に決めてこの行に書く) | 100 以上 | 2 回連続 30 未満 | 製品ページの表示回数は多いがダウンロードが少なければ、製品ページの訴求を変える |
| 取り込みを 1 回以上始めた人のうち、キーボードから返信案を入力した人の割合 | 計測基盤を入れた後に決める (公開前は計測しない) | 30% 以上 | 2 回連続 10% 未満 | 翻訳は読まれるが返信案が使われなければ、返信案を外して翻訳だけにする |

## 必要な機能

- [ ] スクリーンショットからの読み取り (本体アプリ。開くと直近に撮ったスクリーンショットをすぐ選べ、選ぶとその翻訳と返信案が本体アプリの画面に出て、返信案をコピーできる)
- [ ] 取り込みの開始と停止 (本体アプリ。画面全体を選ぶ、取り込み中であることの表示、始める前の同意の画面)
- [ ] 画面の文字の読み取りと、チャットの発言の抜き出し
- [ ] 発言の翻訳 (端末内。言語のダウンロードを本体アプリの画面で済ませる)
- [ ] 返信案の生成 (端末内のモデル。使えない端末では翻訳だけを出す)
- [ ] キーボード: 直前の読み取り結果 (翻訳と返信案) を表示し、返信案をタップで入力する。次のキーボードへ切り替えるキーを持つ
- [ ] 初回の案内 (キーボードの追加の手順、取り込みの説明)
- [ ] 設定 (自分の言語、読み取り結果の削除、利用規約とプライバシーポリシーへのリンク、問い合わせ先)
- [ ] 開発者メニュー (DEBUG ビルドだけ。読み取り結果の見本の保存、診断の記録の表示、返信案を作るモデルの選択)

## デザインの方向

- 仕事で使う道具の見た目にする。2026-11-17 のモック (`documents/design/mock-2026-11-17/index.html`) の色・角の丸さ・余白を使う (owner の発言 2026-11-18: 「UIのテーマ的には仕事で使われる感じがしてて良いと思う」。https://github.com/bannzai/poppo/issues/10#issuecomment-6969023686 )
- 読み取った内容を、アプリ・チャット・人物ごとに分けて見せる (同じ発言: 「できればアプリのアイコンやチャットごと・人物ごとに分かれている感じがいいかな」)。2 通りの案 (`documents/design/mock-2026-11-18/index.html`。左 = 読み取り結果、中央 = キーボード、右 = アプリとチャットごとの一覧) への返答は「全部かも」で、一覧を入口にして、アプリ × チャンネルごとの会話に入り、読み取った時点 (「2 分前の会話」) を横スクロールで送る形 (owner の発言 2026-11-18: 「分け方だけど全部かも。一番右が一覧画面。入ると一番左のようにアプリごとxチャンネルごとに会話がある。2分前の会話。みたいな項目あると嬉しい。2分前の会話。みたいな時系列を横スクロールでペラペラと移動できたら良いかも。画像やch UIがページ送りされる感じ」。https://github.com/bannzai/poppo/issues/10#issuecomment-6971214314 )。この形を描いたモックは `documents/design/mock-2026-11-18-history/index.html`。会話の画面のページは、このモックの右の画面 (読み取った時の画面の画像と翻訳) にし、読み取った時の画面の画像を残す (owner の発言 2026-11-18: 「残す」「ページ送りは一番右の画面かな」。https://github.com/bannzai/poppo/issues/10#issuecomment-6977394937 。「一番右の画面」をこのモックの右の画面と読んだのは agent)。画像と翻訳は本体アプリの中 (端末) に置き、14 日で自動で消す (owner の発言 2026-11-19: 「勧めは本体アプリの中（端末）に置いて 14 日で自動で消す形です → それでよい」。https://github.com/bannzai/poppo/issues/10#issuecomment-6994918880 )。アプリごとの分け方は、アプリの名前を画面から判定せず、利用者が作るセクションで行う (2026-11-19。「決めたこと」の表)。保存する型の案は `documents/design/reading-moments-store-2026-11-19/index.html`

## agent に任せること

- 画面の細部 (文言・余白・色・アイコン) と、画面の中の要素の並べ方
- 読み取った文字から発言を抜き出す方法、翻訳と返信案を作り直す間隔
- テストの書き方、ファイルの分け方、ライブラリを使うかどうか (端末外へ通信するものと費用がかかるものは除く)

## 費用

利用者に配るビルドは端末内だけで処理し、サーバーも外部の API も使わないため、インフラ費用は発生しない。開発者メニューのあるビルドだけ、bannzai が自分の API キーを入れて OpenAI か Gemini を選んだ時に、利用量に応じた費用が bannzai の各社のアカウントにかかる (https://github.com/bannzai/poppo/issues/39 )。この費用の上限は、既にある API キーに付いている上限のままにし、月 10 ドルの上限を新しく設定しない (bannzai の発言: 「既存のkeyなら上限はついているし良い。」 https://github.com/bannzai/poppo/issues/1#issuecomment-7078400587 。キーに付いている上限の額は agent は確かめていない)。開発中は、月ごとに各サービス 10 ドルを超えない程度に使う ( https://github.com/bannzai/poppo/issues/1#issuecomment-7043055903 )。同じビルドで Claude を選んだ時は、利用量に応じた費用が bannzai の Claude Console の workspace にかかる (API キーは使わず、App Attest で認証する。https://github.com/bannzai/poppo/issues/43 )。この費用の上限は、Claude Console に既定で付いている上限のままにし、月 10 ドルの上限を新しく設定しない (bannzai の発言: 「Claudeの方も$10じゃないけどデフォルトでついているよね。」同じコメント。既定の上限の額と、app integration を作った workspace の上限は agent は確かめていない)。アプリの中にも、このリポジトリの設定にも上限は無い。利用者に配るビルドに費用がかかる構成 (端末外のモデル・サーバー) を入れるかは bannzai が決めるため、下の表は埋めていない (埋まるまで、費用を伴う変更はすべて確認に回る)。

## 用語

| 用語 | 定義 | 使わない言い換え |
| --- | --- | --- |
| 本体アプリ | ホーム画面から開く Poppo のアプリ。取り込み・読み取り・翻訳・返信案の生成を行う | メインアプリ・ホストアプリ |
| キーボード | Poppo のカスタムキーボード。他のアプリの入力欄で開き、読み取り結果を表示して返信案を入力する | 拡張・エクステンション |
| 取り込み | 利用者が始めてから止めるまで、本体アプリが画面全体の映像を受け取り続けること | 録画・キャプチャ・画面共有 |
| 発言 | チャットの画面に見えている 1 つの書き込み | メッセージ・投稿 |
| 読み取り結果 | 本体アプリが直前に画面から読んだ発言と、その翻訳と、返信案の組。常に最新の 1 つだけを持つ | 履歴・スナップショット |
| 読み取った時点 | 会話の画面の 1 ページになる、画面の画像と、その時に読んだ発言・翻訳・返信案の組。取り込みでは会話が大きく変わった時に 1 つ、スクリーンショットからの読み取りでは 1 回に 1 つ作る。本体アプリの中に 14 日残す (残す仕組みはまだ実装していない) | 履歴・ログ・スナップショット |
| セクション | 一覧でチャットを分けるまとまり。利用者が自由に作って名前を付ける (「Slack」「仕事」など) | グループ・フォルダ・カテゴリ |
| 返信案 | 読み取った発言に対して本体アプリが作る返信の文。キーボードではタップするとその文が入力欄に入り、本体アプリではコピーできる | 候補・提案・サジェスト |
| スクリーンショットからの読み取り | 利用者が撮ったスクリーンショットを本体アプリで選び、その画像から発言を読んで翻訳と返信案を出すこと。取り込みを始めなくても使える | スクショ翻訳・画像翻訳 |
