型定義 (Swift)

新しく定義するのは ReadingMoment・ChatHeader・ReadingMomentSource の 3 つ。LatestReading (キーボードに渡す読み取り結果) と ReplySuggestion は今ある型をそのまま使う。LatestReading は名前が「最新」だが、読んだ時刻・発言・返信案という中身が同じなので、同じ項目の型を 2 つ作らずに過去の時点にも使う。TranslatedMessage には項目を 1 つ足す (下)。

/// 読み取った時点。画面を 1 回読んだ時の、画面の画像と、その時に読んだ発言・翻訳・返信案の組。
/// 本体アプリの中 (端末) に置き、読んでから 14 日が過ぎたものは消す。キーボードからは読まない
struct ReadingMoment: Codable, Identifiable {
    /// 読み取った時点ごとに振る識別子。画面の画像のファイル名にも使う
    let id: UUID
    /// その時に画面から読んだ発言と、その翻訳と、返信案。画面を読んだ時刻 (capturedAt) もこの中にある
    let reading: LatestReading
    /// どのアプリのどのチャットの画面だったか。画面の上部からチャットの名前を読めなかった時は nil で、
    /// 一覧では「チャットを読み取れなかった画面」の 1 行にまとめる
    let chatHeader: ChatHeader?
    /// 読んだ画面の出どころ
    let source: ReadingMomentSource
}

/// 画面の上部から読んだ、チャットの見出し。一覧の行と、会話の画面のまとまりを決める。
/// まとめる時の比べ方は「見てほしい点 3」(保存するのは読んだままの文字で、比べる時に空白と大文字小文字をそろえる)
struct ChatHeader: Codable {
    /// アプリの名前 (「Slack」「Discord」など)。分からなかった時は nil
    let appName: String?
    /// 画面の上部から読んだままの、チャンネル名か相手の名前 (「#release-team」「Alex」など)
    let chatTitle: String
}

/// 読み取った時点の画面が、どこから来たか
enum ReadingMomentSource: Codable {
    /// 取り込みの間に本体アプリが読んだ画面
    case capture
    /// 利用者が自分で撮って本体アプリで選んだスクリーンショット
    case screenshot
}

今ある型に足す項目 (新しい型ではない)。TranslatedMessage は LatestReading の中に入っているので、キーボードに渡す読み取り結果にも発言した人の名前が入る:

struct TranslatedMessage: Codable {
    let originalText: String
    let translatedText: String
    /// 発言した人の名前。画面から読めなかった時は nil
    let speakerName: String?   // ← 足す。「人物ごとに分かれている感じ」のため
}

置く場所: 本体アプリのコンテナの Application Support/ReadingMoments/。読み取った時点ごとに <id>.json (ReadingMoment) と <id>.jpg (画面の画像) の 2 つのファイルを置く。キーボードと共有する場所 (App Group) には置かない。

見てほしい点

1. 動画を、何の単位で残して、どこで見せるか

「動画も含めて」を、取り込みの間の画面の動画も残す、と読んだ。上の型には動画をまだ入れていない。何を残すかで型が変わるため。

  • 案 A (勧め): 取り込みを始めてから止めるまでを 1 本の動画にして残し、会話の画面のページから「この時点の前後の動画を見る」で開く。型は、取り込み 1 回ごとの CaptureRecording (始めた時刻・止めた時刻・動画のファイル名) を足し、ReadingMoment が取り込みの中の何秒目かを持つ
  • 案 B: 動画は残さず、読み取った時点の画像を増やす (画面が変わるたびに読む)

分かっていること: iOS 27 の SDK に、取り込みを動画のファイルに書き出す API がある。分かっていないこと: 本体アプリが背面にいる間も書き出せるか、14 日分の大きさ、電池への影響 (どれも実機で測る)。動画は、チャット以外の画面 (ホーム画面・ほかのアプリ・通知) も取り込みの間はすべて残る。

2. 無料の利用者のスクリーンショットからの読み取りも残して、一覧に出すか

一覧が本体アプリの入口で、agent の読みでは「一覧と会話の画面」は有料 (有料の範囲は、中身を 1 文で言い直してもらうのを待っている)。このままだと、無料の利用者には入口の一覧が空になる。

  • 案 A (勧め): スクリーンショットから読んだ時点も残し、無料の利用者も一覧と会話の画面で見られる。有料との違いは、取り込みとキーボード (と動画) で付ける。agent が聞き直した有料の範囲の表から「一覧と会話の画面 = 有料」を外すことになる
  • 案 B: 無料の利用者は残さない (今と同じで、読んだその場で見るだけ)。一覧には「取り込みを始める」と「スクリーンショットから読む」だけが出る

3. アプリとチャットの分け方

iOS は、取り込みの間に前面のアプリが何かを教えてくれない (ScreenCaptureKit の該当の API が iOS で使えない)。そのため、チャットの名前は画面の上部の文字から読み、同じ文字なら同じチャットとして 1 行にまとめる。

  • 空白と大文字小文字だけが違う時 (「#release-team」と「# Release-Team」) は同じチャットとみなす。文字そのものを読み違えた時 (「#release-team」と「#re1ease-team」) は別の行になる。似た名前をまとめる寄せ方はしない
  • 同じチャットでも、アプリの名前を判定できた回とできなかった回は別の行になる (判定できなかった回は「アプリを判定できなかったチャット」の見出しの下に出る)
  • アプリの名前 (appName) は、画面の見た目から決められた時だけ入れる。決められない時は nil で、一覧では「アプリを判定できなかったチャット」の見出しの下に並べる。利用者に選んでもらう操作は最初は作らない
  • 発言した人の名前も画面の文字から読むので、読めない画面では人物ごとに分かれない

4. 型に入れなかったもの

  • 写真ライブラリの元の画像への参照: スクリーンショットから読んだ時点も、画像を本体アプリの中に写して置く。置く場所を 1 つにして、14 日で消す・全部消すを同じ仕組みにするため
  • お気に入り・メモ・検索: 頼まれていないので入れていない
  • 端末をまたぐ同期: 端末の外へ出さない方針のため入れていない
