# 検証用の状態の作り込みは開発者メニューで行う

動作確認で到達困難な状態 (画面から読み取った文言の見本・翻訳結果・返信案・取り込み中の状態等) は、アプリ内の開発者メニューに操作を追加して作る。本アプリの中心の流れ (他のアプリの画面の取り込み → キーボードへの表示) は simulator では再現できない部分があるため (AGENTS.md「検証方法」)、取り込みを通さずに後段 (翻訳・返信案の表示・キーボードへの受け渡し) を確かめる入口を開発者メニューに置く。

## ルール

- 開発者メニューの導線と検証用の操作は DEBUG ビルドだけで有効にし、App Store 配布のビルドに入れない
- 操作要素には `accessibilityIdentifier` (`debug_` prefix) を付ける (リモート simulator の操作ツールからの検出用)
- デバッグ操作は冪等にする (再実行してもデータが壊れない)
- 起動引数・環境変数で状態を作る方式は、開発者メニューで置き換えられない時 (アプリの起動完了前に効かせる設定等) だけにする (`~/.claude/rules/debug-menu-first-for-hard-to-reach-states.md`)
- 実装パターンは debug-function skill を参照する
